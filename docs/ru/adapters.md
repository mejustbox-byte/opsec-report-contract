# Адаптеры проверенных производителей

Guard: только основной response-0.2. Проверяются поставляемая исходная схема и согласованность лимитов/покрытия/остановки. Повторные check/asset группируются с уникальными ссылками на строки; более 128 ссылок отклоняют преобразование. Fail сохраняется. Pass не выводится из отсутствия. Всегда остаётся finding_only_source, поскольку источник не перечисляет все выполненные пары check/asset. Оператор явно задаёт область, UTC-время и synthetic-класс.

AD: report_schema_version=1 проверен по коммиту 6c5687f7ffe0f57825bb29ff86453c6b4e9a914e, report.py/rules.py. Проверяются сводка, статусы, полное покрытие pass/fail, наличие свидетельств и синтаксис хеша входа. unknown/not_run становятся not_tested; явные pass/fail сохраняются. Область, synthetic, версии движка/правил и время сохраняются. ID свидетельств становятся SHA-256 ссылками; исходные причины/описания/рекомендации заменяются общей инструкцией. Хеширование не анонимизирует и не подтверждает происхождение.

AD-фикстура создана этим кодом из safe.synthetic.json: это не реальный экспорт и не Windows-тест. Преобразование намеренно теряет детали. Будущему формату нужен новый адаптер/корпус; общий/Office/секретный ответы Guard пока отклоняются.
