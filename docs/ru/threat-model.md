# Модель угроз и границы доверия

Активы: приватные отчёты, нормализованные идентификаторы/ссылки, локальные выходы и смысл выводов для reviewer. Входной JSON/narrative управляются атакующим. Угрозы: неверные/глубокие/большие данные, повторные ключи, поддельная полнота, потеря статусов, HTML/script injection, сетевые схемы и перезапись.

Контроли: ограниченная загрузка обычного файла, строгий JSON, схема без лишних полей, согласованность, уникальность идентичностей, консервативные адаптеры/сравнение, экранирование/CSP, запрет сетевых refs и эксклюзивная запись. Сфабрикованный согласованный pass может пройти: это не аутентификация свидетельств. Сообщения способны раскрывать секреты; redacted=true не очиститель. Локальный код/зависимости/ОС доверенные.

Остаточные риски: происхождение, гонки/замена предков, hardlinks, ошибки runtime/парсера, отсутствие квот RAM/CPU, повторная идентификация, устаревшие свидетельства и неполная проверка источника. Реальные фикстуры не публикуются. Изоляция/патчи runtime — отдельная обязанность оператора; исправления и сетевые проверки учётных данных не выполняются.
